# Dawn

**Day thermal to color for drone imagery.** Dawn turns a daytime thermal frame from a drone (640×512, one channel) into the matching daytime RGB image, in two network steps, with brightness and color uncertainty maps.

It treats thermal as a one-channel image and splits the job in two. Brightness is a per-region curve of thermal intensity, if a fit check shows that works; color is generated by flow matching, conditioned on a LoRA-tuned DINOv3 that learns to see thermal the way it sees daylight. The training data are real thermal/RGB day pairs from [DroneVehicle](https://huggingface.co/datasets/McCheng/DroneVehicle), kept only if they pass a strict alignment filter. The full design is in [`docs/Dawn Night-Vision to Day Colorization for Drone Imagery.md`](docs/Dawn%20Night-Vision%20to%20Day%20Colorization%20for%20Drone%20Imagery.md).

> **Honest framing.** Thermal measures heat, not light. Lane paint, text, signs and the paint color of a car have no heat signature, so whatever the model puts there is a learned guess, not a measurement. Invented detail is accepted in this project; the layout of the scene comes from the thermal image. The uncertainty maps show where the model is unsure, not where it is right.

| Results | None yet. No numbers are claimed here |

Few pairs survive the filter: of the 28,411 DroneVehicle pairs, about 9,300 are daytime and 5,921 pass alignment and dedup (3,990 train, 363 val, 1,568 test; `data/manifests/logs/summary.md`). 2,581 of them were aligned by the edge-correlation fallback instead of by boxes, so they are less trustworthy and have no moving mask (`data/manifests/fallback_pairs.txt`). Without the fallback it is 3,340, and with the plan's original edge check 1,569. A small training set is the largest risk the plan names, and the audit exists to decide what else to loosen.

## Installation

```bash
git clone https://github.com/rzx01/dawn.git
cd dawn
pip install -e ".[dev]"
```

- Python ≥ 3.10, PyTorch ≥ 2.1. The data pipeline runs on CPU.
- The model phase wants PyTorch built for CUDA 12.8 or newer on an RTX 5060 Ti (16 GB).
- DINOv3 weights are gated. Accept the [license on Hugging Face](https://huggingface.co/facebook/dinov3-vits16plus-pretrain-lvd1689m) and `export HF_TOKEN=...`. The encoder loads through `timm` by default; `pip install -e ".[transformers]"` adds the other backend. Tests never download weights.

```bash
pytest                       # CPU only, offline, does not need the dataset
ruff check dawn scripts tests
```

## Data preparation

Download [McCheng/DroneVehicle](https://huggingface.co/datasets/McCheng/DroneVehicle) (about 14 GB) to `data/DroneVehicle/` so that it holds `{train,val,test}/{split}img`, `{split}imgr`, `{split}label` and `{split}labelr` (RGB images, thermal images, RGB XML, thermal XML). Paths and every threshold are in `configs/data.yaml`.

```bash
python scripts/prepare_dronevehicle.py stats    # per-stem checks, luminance, perceptual hashes (minutes, once)
python scripts/prepare_dronevehicle.py day      # luminance histogram + contact sheets: choose the day cutoff by looking
python scripts/prepare_dronevehicle.py align    # box matching, RANSAC similarity, acceptance, edge check
python scripts/prepare_dronevehicle.py dedup    # drop val/test pairs that near-duplicate a train pair
python scripts/prepare_dronevehicle.py write    # aligned PNGs, the three manifests, summary.md
python scripts/audit_alignment.py               # 100 accepted + 100 rejected pairs with thermal edges over the RGB
```

What the pipeline does to the 28,411 pairs (840×712 frames with a 100-px white border):

1. **Crop** the border: 640×512.
2. **Day filter** on the median linear luminance of the RGB (`day_filter.min_lum_median`). Luminance alone cannot separate day from dusk perfectly: a few percent of the admitted frames are dusk or night.
3. **Match** each thermal box to the nearest RGB box of the same class (mutual nearest neighbours); boxes that are exact copies across the two label files are not evidence and are left out.
4. **Fit** a similarity transform by RANSAC (a homography only if the similarity's residual alone fails), and **accept** only with enough matches, inlier ratio, a small median residual, and sane scale, rotation and shift.
5. **Edge check**: gradient-magnitude correlation between thermal and RGB, independent of the boxes. It only rejects pairs that are more than about 3 px off or clearly worse after the warp.
6. **Edge-correlation fallback** for the pairs the boxes cannot judge (copied labels, too few vehicles): a global translation estimated from the same edge correlation, accepted only with a clear single peak and agreeing image quadrants. These pairs are listed separately and carry no moving mask.
7. **Warp** the thermal onto the RGB frame (the RGB is never resampled), with a validity mask and a moving-vehicle mask, and write everything once as PNG under `data/dronevehicle_aligned/`.

Outputs that are committed: `data/manifests/{train,val,test}_pairs.txt` (the final lists) and `data/manifests/logs/{day,align,dedup}.csv` plus `summary.md` (every decision, with the fitted transform of every pair). Everything bulky stays in `data/` and `outputs/`, which are ignored. Re-running is idempotent; `--force` redoes finished work.

The aligned pairs are served by `dawn.data.pairs.AlignedPairs` (thermal `(1, 512, 640)` = code / 255, linear RGB `(3, 512, 640)`, a `valid` and a `moving` mask, a `fallback` flag; flips and a random thermal contrast curve in training). Conventions, coordinate systems and every definition are in [`docs/conventions.md`](docs/conventions.md).

## Known limitations

1. **Invented detail.** Anything without a heat signature (paint, text, lane markings, a car's color) is guessed. Read the uncertainty maps next to the output.
2. **A small training set.** Only the pairs that pass a strict alignment filter are used, and the filter currently keeps about 63% of the day pairs (36% by boxes alone, the rest through the edge fallback). The thresholds are under review.
3. **Residual misalignment.** The cameras are not co-registered; pairs are aligned to roughly a pixel or two, and vehicles that moved between the exposures are masked, not fixed.
4. **Day only.** Night pairs and other thermal cameras are out of scope.
5. **Nothing is trained or measured yet.** Speed and quality numbers will come from the model phase.
